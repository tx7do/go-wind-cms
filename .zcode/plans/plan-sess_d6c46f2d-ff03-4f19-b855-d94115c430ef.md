# OpenSearch 集成实现方案（v1：post + post_translation）

## 一、背景与现状结论

项目已铺好 ES/OpenSearch 基础设施骨架，但接入断裂、配置错位，且租户隔离机制对 ES 零覆盖。具体：

1. **容器在跑**：`docker-compose.{,libs.}yaml` 起 `opensearchproject/opensearch`（hostname `opensearch`，9200 端口，admin 密码 `OPENSEARCH_INITIAL_ADMIN_PASSWORD`）。
2. **客户端库已引**：`go.mod` 有 `github.com/elastic/go-elasticsearch/v9`、`github.com/tx7do/kratos-bootstrap/database/elasticsearch`、`github.com/tx7do/go-crud/elasticsearch`（封装了 Index/Search/Delete/CreateIndexTemplate 等完整能力）。
3. **工厂是死代码**：`app/core/service/internal/data/data.go:42` 的 `NewElasticSearchClient` 未进入 `data/providers/wire_set.go` 的 ProviderSet，`wire_gen.go` 从不调用它，全后端无业务代码引用。
4. **配置双重错位（即使接上也会启动失败）**：
   - YAML 键 `elastic_search`（`data.yaml:18`）与 bootstrap proto 字段名 `elasticsearch` 不匹配，kratos 用 `protojson` + `DiscardUnknown:true` 加载（`kratos/v2@v2.9.2/config/reader.go:169`），不匹配的键被**静默丢弃** → `cfg.Data.Elasticsearch == nil` → `NewClient` 报 `"elasticsearch config is nil"`。
   - 地址 `http://elasticsearch:9200` 与容器 hostname `opensearch` 不匹配；凭据 `elastic`/`${elastic_password}` 与 OpenSearch 的 `admin`/`OPENSEARCH_INITIAL_ADMIN_PASSWORD` 不匹配。
5. **租户隔离对 ES 零覆盖**：ent 层的 `rule.TenantPrivacy`（外部 `go-crud/entgo`）只作用于 ent 生成的 SQL，对 ES 文档/查询无任何兜底。且该策略对 `SystemViewer`/平台管理员**直接跳过过滤**——ES 搜索路径不能复用这个 bypass 语义。
6. **asynq 是唯一可用异步通道**：server 已 wire、Redis 后端就绪（`asynq_server.go` + `server.yaml` asynq 段），但目前唯一订阅者 `"backup"` 是空操作 stub。`pkg/eventbus`（进程内 pub/sub）和 `ent/broker.go` 均为死代码，无 outbox。
7. **DI 模式**：本服务无聚合 `Data` 结构，每个 repo 直接持有所需 client，Wire 按 repo 逐个注入（参考 `file_repo.go` 的 `NewFileRepo(ctx, entClient)` 与 `wire_gen.go:34-40` 的 ent 注入链）。

## 二、架构设计

### 数据流

```
写路径：
  API → PostRepo.Create/Update/Delete (ent tx)
     └─ tx 提交成功后 → TaskService 入队 asynq "search.reindex" 任务
                          (payload: {entity, id, tenant_id, op})
                              ↓
  asynq worker → SearchService.ReindexPost (后台 ctx，注入 SystemViewer 读 DB)
     └─ PostRepo.Get → 取 DB 真实数据(含 tenant_id 字段)
     └─ SearchRepo.IndexPost / DeletePost → 写/删 ES 文档
        (ES 文档 tenant_id = DB 记录的 tenant_id，非 viewer)

读路径（前台搜索）：
  App HTTP /search → core gRPC SearchPosts
     → SearchService.Search
        └─ 强制 maybeTenantFromViewer(ctx): hasTenant==false → 返回空
        └─ ES query 必带 term{tenant_id: viewer.tid} + language filter
        └─ 返回命中（仅本租户、本语言）

自愈路径：
  asynq periodic task（每小时）→ SearchService.ReindexAll
     └─ 遍历所有 post → 逐条 IndexPost（修复崩溃窗口内的漂移）
```

### 多租户隔离原则（安全核心）

| 路径 | viewer | tenant_id 来源 | bypass 行为 |
|---|---|---|---|
| 写入 ES（reindex handler） | SystemViewer（注入） | DB 记录的 tenant_id 字段 | 跨租户读取是必须的（系统级修复） |
| 搜索（前台 API） | UserViewer | viewer.tid | **tid==0 返回空，绝不 bypass** |
| 删除 ES 文档 | SystemViewer（注入） | DB 记录的 tenant_id | 按 post_id + tenant_id 双重定位删除 |

关键差异：搜索路径**不接受 SystemViewer bypass**——这是与 ent 层的最大区别，因为 ES 无自动策略兜底，必须手动且不可绕过。

### 索引设计

- **索引名**：`posts`（共享索引，所有租户文档同索引）
- **文档 id**：`{post_id}_{language}`（同一 post 的每种语言翻译各一个 ES 文档，避免字段冲突）
- **mapping**：

| 字段 | 类型 | 分词器 | 说明 |
|---|---|---|---|
| `tenant_id` | keyword | — | 必填，搜索强制 term 过滤 |
| `post_id` | keyword | — | 对应 DB 主键，删除按此 |
| `language` | keyword | — | 前台按语种过滤 |
| `code` | keyword | — | post code |
| `status` | keyword | — | 发布状态过滤 |
| `title` | text | smartcn | 来自 post_translation |
| `summary` | text | smartcn | 来自 post_translation |
| `content` | text | smartcn | 来自 post_translation |
| `publish_time` | date | — | 排序用 |

- **不索引**：`author_id`、`author_name`、`password_hash`、`custom_fields`（敏感/无用）
- **索引模板**：用 `CreateIndexTemplate` 建 `posts_template`，确保 mapping 一致 + 分词器绑定 smartcn
- **ILM**：v1 不设，v2 再加滚动

## 四、安全考量清单

1. **搜索路径不 bypass**：`SearchService.Search` 第一行 `maybeTenantFromViewer`，`hasTenant==false` 直接返回空——这是与 ent 层 SystemViewer bypass 的有意差异，因为 ES 无自动兜底。
2. **ES 文档 tenant_id 来自 DB**：reindex handler 用 SystemViewer 读 DB（特权），但写入 ES 的 tenant_id 取自 DB 记录字段值，保证数据归属准确。
3. **删除双重定位**：`DeletePost` 按 `post_id` + `tenant_id` 双条件删，防止误删他租户文档。
4. **不索引敏感字段**：mapping 不含 author_id/password_hash/custom_fields。
5. **前台 API 不暴露 tenant_id 参数**：tenant_id 由 viewer 注入，客户端不可伪造。
6. **凭证对齐**：修复 `data.yaml` 的地址/用户名/密码与 OpenSearch 容器一致，并改用 `elasticsearch` 键名。
7. **roadmap 项（非 v1）**：启动时 fail-fast 校验 ES 密码非默认值（与第 8 轮审计对 JWT key 的要求一致，审计 line 238 已列为待办）。

## 五、风险与待验证项

1. **OpenSearch smartcn 兼容性**：阶段 1 必须先验证 `analysis-smartcn` 可装。若不可用，回退 `analysis-icu` + ngram（中文检索质量下降），并在索引 mapping 中改分词器字段。
2. **OpenSearch 与 ES v9 客户端 API 差异**：`go-crud/elasticsearch` 封装用的是 ES v9 客户端。OpenSearch 兼容 ES 7.10 REST API，v9 客户端调用时若用了 7.10 之后的 API 可能报错。需在阶段 3 实测 `IndexDocument`/`Search`/`CreateIndexTemplate` 是否正常。
3. **无 outbox 的崩溃窗口**：双写入队失败或 worker 崩溃期间，文档可能短暂不在 ES。由周期 ReindexAll 修复（最长 1 小时滞后）。内容站可接受；若不可接受，v2 加 outbox 表。
4. **asynq payload 大小**：reindex payload 只含 id（不含文档内容），体积小，无溢出风险。
5. **索引膨胀**：共享索引下所有租户数据混合，需关注 ES 磁盘容量。v1 不做 ILM，roadmap 加。

## 六、v1 不做项（边界）

- 不做高亮（`SearchWithHighlight`）→ v2
- 不做聚合/facets → v2
- 不做搜索排序调优 → v2
- 不做 ILM 滚动 → v2
- 不做 page/section/tag/category 索引 → v2，模式稳固后扩展
- 不做后台管理端搜索（admin search）→ v2
- 不做 outbox 事务性保证 → v2 评估
