## 验证码功能同步计划

从 go-wind-admin 同步登录验证码（captcha）功能到 go-wind-cms。CMS 前端 `auth.ts` 已有 `fetchGenerateCaptcha`/`generateCaptcha`/`useGenerateCaptcha` 调用，但因后端 proto 和 API 缺失而不可用。本次补齐完整链路。

### 一、后端（core service）

**1. Proto 定义** — `backend/api/protos/authentication/service/v1/authentication.proto`
- 在 `service AuthenticationService` 块末尾（WhoAmI rpc 之后、闭合 `}` 之前）新增两个 rpc：`GenerateCaptcha` 和 `VerifyCaptcha`
- 在文件末尾新增三个 message：`GenerateCaptchaResponse`（captcha_id + image_base64）、`VerifyCaptchaRequest`（captcha_id + user_input）、`VerifyCaptchaResponse`（valid bool），字段定义与 admin proto 完全一致

**2. 重新生成 Go API 代码** — 运行 `make api`（`buf generate`）
- 重新生成 `authentication.pb.go`、`authentication_grpc.pb.go`、`authentication_http.pb.go`、`authentication.pb.validate.go`、`authentication.pb.redact.go`、`openapi.yaml`

**3. 新增 `netutil.HeaderFromContext`** — `backend/pkg/netutil/client_ip.go`（新建文件）
- 从 admin 项目逐字复制 `HeaderFromContext` 函数（从 kratos transport context 提取 HTTP header），以及所需的 imports（context, net/http, kratos transport + khttp）
- 同时复制 `ClientIPFromContext` 函数（admin 中同文件存在，CMS 当前无此函数但属于同一基础设施）

**4. `NewCaptcha` 工厂** — `backend/app/core/service/internal/data/data.go`
- 新增 import：`github.com/tx7do/go-utils/captcha`、`go-wind-cms/pkg/serviceid`、`time`
- 新增 `NewCaptcha(rdb *redis.Client) *captcha.Captcha` 函数，使用与 admin 相同的 5 个选项（DriverString、10min expire、key prefix `serviceid.ProjectName+":captcha"`、6 字符、字符表 `"ABCDEFGHJKLMNPQRSTUVWXYZ23456789"`）

**5. Wire 注入** — `backend/app/core/service/internal/data/providers/wire_set.go`
- 在 ProviderSet 中添加 `data.NewCaptcha`（与 admin 相同位置，紧随 `data.NewPasswordCrypto` 之后）

**6. `AuthenticationService` 改造** — `backend/app/core/service/internal/service/authentication_service.go`
- 新增 import：`github.com/tx7do/go-utils/captcha`、`go-wind-cms/pkg/netutil`、`strings`
- struct 新增字段 `captchaClient *captcha.Captcha`
- 构造函数 `NewAuthenticationService` 新增参数 `captchaClient *captcha.Captcha`，赋值到 struct 字段
- 新增常量：`headerCaptchaID = "X-Captcha-Id"`、`headerCaptchaValue = "X-Captcha-Value"`、`CaptchaEnabled = true`
- 新增 `verifyLoginCaptcha(ctx) bool` 方法（逐字复制 admin 实现：检查开关/nil fail-open/HeaderFromContext/TrimSpace/Verify）
- `doGrantTypePassword` 顶部（tenant 解析之前）插入验证码闸门：`if !s.verifyLoginCaptcha(ctx) { return nil, authenticationV1.ErrorBadRequest("invalid or missing captcha") }`
- 新增 `GenerateCaptcha` 和 `VerifyCaptcha` HTTP handler 方法（逐字复制 admin 实现，使用 `s.captchaClient.Generate/Save/Verify`）

**7. 重新生成 Wire** — `backend/app/core/service/cmd/server/wire_gen.go`
- 运行 `make wire` 重新生成 wire_gen.go，使其包含 `captcha := data.NewCaptcha(client)` 并将 `captcha` 传入 `NewAuthenticationService`

**8. CORS 配置** — `backend/app/core/service/configs/server.yaml`
- 当前 core service 的 server.yaml 只有 grpc 配置（无 rest/cors 段）。验证码 header 通过 gRPC metadata 传递（ent middleware 的 `OperatorMetadata` 机制），不经过 HTTP CORS，因此**无需修改 server.yaml**

### 二、前端（vue-vben）

**9. `captcha-headers.ts`**（新建）— `frontend/admin/apps/admin/src/transport/rest/captcha-headers.ts`
- 逐字复制 admin 的 `setCaptchaHeaders`/`consumeCaptchaHeaders` 模块级持有器（一次性消费语义）

**10. `transport/rest/index.ts`** — 新增 `export * from './captcha-headers';`

**11. `transport/rest/request-api.ts`** — 新增 `headers?: Record<string, string>` 参数，透传到 axios request 选项

**12. `api/client.ts`** — import 改为 `import { consumeCaptchaHeaders, requestApi } from '#/transport/rest'`；`unary` 中调用 `consumeCaptchaHeaders()` 获取一次性 header 并传入 `requestApi`

**13. `stores/authentication.store.ts`** — 新增 `import { setCaptchaHeaders } from '#/transport/rest'`；`authLogin` 中 `loginMutation.execute` 之前，若 `params.captchaId && params.captchaValue` 存在则调用 `setCaptchaHeaders`（这些参数由 login.vue 的 handleSubmit 传入）

**14. `login.vue`** — 新增验证码 UI：
- 新增 imports：`h, onMounted, ref`（vue）、`fetchGenerateCaptcha`（composables）
- 新增 captcha 状态 refs：`captchaId`、`captchaImage`、`captchaLoading`
- 新增 `refreshCaptcha()` 函数（调用 fetchGenerateCaptcha 获取 captchaId+imageBase64）
- `onMounted` 调用 `refreshCaptcha()`
- 新增 `renderCaptchaImage()` 函数式组件（点击刷新、img 渲染 base64、loading 占位）
- formSchema 新增 captcha 输入字段（fieldName `captchaValue`，suffix 为 renderCaptchaImage）
- `@submit` 从 `authStore.authLogin` 改为本地 `handleSubmit` 包装函数（合并 captchaId 后调用 authLogin，失败时 refreshCaptcha）

**15. i18n** — `frontend/admin/packages/locales/src/langs/{en-US,zh-CN}/authentication.json`
- 新增 3 个 key：`captcha`、`captchaTip`、`captchaRefresh`（en-US 和 zh-CN 各自翻译，值与 admin 一致）

**16. 重新生成前端 TypeScript** — 运行 `buf generate --template buf.admin.typescript.gen.yaml`
- 使 generated `index.ts` 包含 `GenerateCaptcha` 方法、`GenerateCaptchaResponse`/`VerifyCaptchaRequest`/`VerifyCaptchaResponse` 类型，修复 auth.ts composable 的引用

### 三、验证

**18. 前端类型检查** — `vue-tsc --noEmit` 确认 auth.ts 的 GenerateCaptcha 引用已解决、无新增类型错误
