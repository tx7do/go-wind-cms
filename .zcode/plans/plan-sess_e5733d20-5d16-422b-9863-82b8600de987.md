# Token 存储安全加固（AUD9-M4/M5 修复）

## 背景
第 9 轮审计 AUD9-M4（Flutter token 明文存 SharedPreferences）+ AUD9-M5（Web 三端 token 明文存 localStorage）。
原计划改 httpOnly Cookie，但调研发现硬约束：kratos-bootstrap 依赖库的 CORS 不支持 credentials（结构体无字段，需 fork）、生产跨子域需 `SameSite=None` 引入 CSRF 面、app BFF refresh token 被禁用。Cookie 方案是需架构评审的大决策，**留作后续 P1 议题**。

本次做**与 Cookie 无关、无论 Cookie 方案走不走都该做**的两个 interim 修复：
1. 修复 Flutter 鉴权拦截器未注册的 bug（调研意外发现）
2. 各端 token 落盘加密（消除明文，复用各端已有 AES 工具）

## 改动一：修复 Flutter AuthenticationInterceptor 未注册 bug

**问题**：`http_client.dart:18-24` 的 `_configureInterceptors` 把 `AuthenticationInterceptor` 整个注释掉，导致 Flutter 端所有需鉴权的 API 调用都不带 Authorization 头（鉴权链路断裂）。

**文件**：`frontend/app/flutter_app/lib/src/core/transport/http/http_client.dart`
- 取消 `AuthenticationInterceptor` 的注释并正确注入 `authService`
- 需要确认 `AuthService`/`UserAuthCache` 的 GetIt 注册时机，保证注入时它们已就绪（若顺序问题，改用懒查找而非构造注入）

**配套**：审计 AUD9-M4 要求 Flutter token 不再明文存 SharedPreferences。但换 `flutter_secure_storage` 需加新依赖 + 本环境无 dart 工具链无法验证。本次先把拦截器修好（恢复鉴权），secure storage 作为后续（在 .zcode/plans/audit-round9-report.md 已记录）。

## 改动二：Web 三端 token 落盘加密（AUD9-M5）

**现状**：Vue/React/Admin/Taro 四端的 `core/storage/storage.class.ts` 均无加解密，token 明文落 localStorage。
**已有工具**：四端都有 `utils/crypto.ts`（CryptoJS AES-CBC 封装），Flutter 有 `encrypt` 包。

**做法**：在 `StorageManager` 的 `setItem`/`getItem` 落盘/读取处对 token 类键值做 AES 加解密。具体落点：
- Vue `app/core/storage/storage.class.ts`
- React `src/core/storage/storage.class.ts`
- Taro `src/core/storage/storage.class.ts`
- Admin 的 token 走 pinia-plugin-persistedstate（不经 StorageManager），需在 access store 的 persist transform 里加解密

**注意**：
- 只对 token 相关 key 加密（避免全量加密性能开销），用 key 名匹配（如 `access-token`/`refresh-token`）
- AES key 复用各端已有的（Vue `aesKey`、React `NEXT_PUBLIC_AES_KEY`、Admin `VITE_AES_KEY`、Taro `AES_KEY`）—— 这些 key 本来就用于密码加密，复用合理
- 加密是 interim 方案：XSS 仍可在内存读到解密后的 token，但至少 localStorage 里不是明文（防浏览器扩展/物理访问/备份读取）。真正根治是 httpOnly Cookie（后续）

## 不在本次范围
- httpOnly Cookie 方案（需 fork 依赖库 + CSRF 评估 + app BFF refresh 配置，留作 P1 架构议题）
- Flutter secure_storage（需新依赖 + dart 工具链验证，留作后续）
- Taro 小程序端保持 token 模式（小程序不支持 cookie，加密落盘已覆盖）

## 验证
- Web 端：tsc/vue-tsc 类型检查通过
- Flutter：本环境无 dart 工具链，做人工审查（确认拦截器注册逻辑、AuthService 注入时机正确）
- 人工确认：localStorage 里 token 键的值不再是明文（加密后的 base64）

## 风险
- Flutter 拦截器启用后，若 `AuthService` 注入时机不对会启动崩溃 —— 需确认 GetIt 注册顺序（UserAuthCache 在 transport 之前注册）
- token 加密后旧明文 token 需重新登录（无迁移逻辑，可接受 —— 安全升级）
